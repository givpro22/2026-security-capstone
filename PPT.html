종단간 암호화(E2EE)란 무엇인가?

"중간 통로를 믿지 않는 보안"

보내는 사람과 받는 사람 양 끝(End)에서만 메시지를 읽을 수 있는 방식입니다.

중간에 거치는 서버조차 절대로 평문을 볼 수 없으며, 오직 암호화된 데이터만 전달합니다.

비유: 받는 사람만 열 수 있는 자물쇠 상자에 편지를 넣어 보내는 것과 같습니다.

일반 암호화 vs 종단간 암호화

일반 HTTPS 암호화

서버가 데이터를 잠시라도 볼 수 있는 구조

  • 서버 해킹 시 데이터 유출 위험
  • 운영자가 메시지 열람 가능

예: 카카오톡 일반 대화, 페이스북 DM

종단간 암호화 (E2EE)

서버는 오직 암호문만 전달하는 구조

  • 서버 해킹 시에도 대화 내용 안전
  • 법적 요청에도 제공할 평문 없음

예: Signal, WhatsApp, iMessage

E2EE가 막아주는 주요 위협

  • 내부자 위협: 서버 관리자나 직원의 무단 데이터 열람 원천 차단
  • 서버 해킹: 서버 DB가 통째로 유출되어도 암호화된 상태라 해독 불가
  • 네트워크 도청: 공용 와이파이나 통신사 구간에서의 가로채기 방어
  • 법적 데이터 강제 집행: 기술적으로 평문 제공이 불가능한 구조
  • 중간자 공격 (MitM): 통신 경로 중간에서 데이터를 조작하거나 훔쳐보는 공격 방어

암호화 프로토콜의 역할

E2EE는 추상적인 목표입니다. 이를 실제로 구현하기 위해서는
키를 어떻게 생성하고 갱신할지에 대한 구체적인 설계도(프로토콜)가 필요합니다.

Noise Protocol

모듈형 핸드셰이크 프레임워크

2016년 Trevor Perrin이 설계한 현대적인 보안 프레임워크입니다. 다양한 핸드셰이크 패턴을 조합하여 목적에 맞는 암호화 통신을 구축할 수 있습니다.

  • 단순하고 가벼운 구조 (약 70p 명세)
  • WireGuard VPN, WhatsApp 등에서 사용

Signal Protocol

메시징 보안의 표준

현존하는 가장 강력한 보안 프로토콜입니다. Double Ratchet 알고리즘을 통해 메시지 단위의 개별 보안을 제공합니다.

  • X3DH 키 교환 + Double Ratchet 결합
  • 오프라인 메시지 암호화 완벽 지원

Noise vs Signal 프로토콜 비교

구분 Noise Protocol Signal Protocol
학습/구현 복잡도 낮음 (모듈형) 높음 (복합 알고리즘)
순방향 보안(FS) 세션 단위 제공 메시지 단위 제공 (강력함)
오프라인 메시지 직접 설계 필요 기본 내장 (PreKey 시스템)
주요 사용처 VPN, IoT 기기, 스트리밍 채팅 앱, 1:1 메시징 서비스

과거 보호

동시 작동 래칫

"보안을 멈추지 않는 톱니바퀴"

1. KDF 래칫: 메시지 한 건마다 암호 키를 한 칸씩 진행시킵니다.

2. DH 래칫: 대화가 오고 갈 때마다 완전히 새로운 키 쌍으로 갱신하여 보안 수준을 초기화합니다.

이 두 가지가 결합되어 해커가 중간에 키를 하나 훔쳐도 다음 메시지는 다시 풀 수 없는 강력한 복구력을 가집니다.

오프라인 메시지 암호화 설계

선불키(PreKeys) 시스템

상대가 접속 중이 아닐 때도 보안 채팅을 시작하는 방법입니다.

  • 사용자가 미리 일회용 공개키를 서버에 업로드
  • 발신자는 서버에서 이 키를 가져와 첫 메시지 암호화
  • 수신자는 나중에 접속하여 자신의 비밀키로 복호화

X3DH 프로토콜을 통해 이를 구현할 예정입니다.

실제 E2EE 적용 사례

Signal & WhatsApp: 프로토콜의 원조이자 가장 광범위한 사용자 기반

Messenger: '비밀 대화' 모드를 통해 Signal Protocol 선택적 적용

WireGuard: Noise Protocol을 활용한 고성능 VPN 보안 구축

프로젝트 기술 스택 (Tech Stack)

  • Frontend: React + Vite 기반의 웹 클라이언트 / libsodium-wrappers
  • Backend: Python FastAPI + Uvicorn / 비동기 소켓 통신
  • Database: SQLite + SQLAlchemy (사용자 메타데이터 및 암호문 저장)
  • Cryptography: libsodium (NaCl), Curve25519, ChaCha20-Poly1305
  • Real-time: WebSocket을 이용한 실시간 양방향 메시지 중계

시스템 아키텍처 및 데이터 흐름

"Zero-Knowledge" 서버 설계

1. 모든 암호화와 복호화는 클라이언트(React) 브라우저 내에서 수행됩니다.

2. 서버는 오직 암호문(Ciphertext)만 전달하며 평문에 절대 접근할 수 없습니다.

3. 비밀키는 서버로 전송되지 않고 클라이언트의 Local Storage에 안전하게 보관됩니다.
