종단간 암호화(E2EE)란 무엇인가?

"중간 통로를 믿지 않는 보안"

보내는 사람과 받는 사람 양 끝(End)에서만 메시지를 읽을 수 있는 방식입니다.

중간에 거치는 서버조차 절대로 평문을 볼 수 없으며, 오직 암호화된 데이터만 전달합니다.

비유: 받는 사람만 열 수 있는 자물쇠 상자에 편지를 넣어 보내는 것과 같습니다.

일반 암호화 vs 종단간 암호화

일반 HTTPS 암호화

서버가 데이터를 잠시라도 볼 수 있는 구조

  • 서버 해킹 시 데이터 유출 위험
  • 운영자가 메시지 열람 가능

예: 카카오톡 일반 대화, 페이스북 DM

종단간 암호화 (E2EE)

서버는 오직 암호문만 전달하는 구조

  • 서버 해킹 시에도 대화 내용 안전
  • 법적 요청에도 제공할 평문 없음

예: Signal, WhatsApp, iMessage

E2EE가 막아주는 주요 위협

  • 내부자 위협: 서버 관리자나 직원의 무단 데이터 열람 원천 차단
  • 서버 해킹: 서버 DB가 통째로 유출되어도 암호화된 상태라 해독 불가
  • 네트워크 도청: 공용 와이파이나 통신사 구간에서의 가로채기 방어
  • 법적 데이터 강제 집행: 기술적으로 평문 제공이 불가능한 구조
  • 중간자 공격 (MitM): 통신 경로 중간에서 데이터를 조작하거나 훔쳐보는 공격 방어

암호화 프로토콜의 역할

E2EE는 추상적인 목표입니다. 이를 실제로 구현하기 위해서는
키를 어떻게 생성하고 갱신할지에 대한 구체적인 설계도(프로토콜)가 필요합니다.

Noise Protocol

모듈형 핸드셰이크 프레임워크

2016년 Trevor Perrin이 설계한 현대적인 보안 프레임워크입니다. 다양한 핸드셰이크 패턴을 조합하여 목적에 맞는 암호화 통신을 구축할 수 있습니다.

  • 단순하고 가벼운 구조 (약 70p 명세)
  • WireGuard VPN, WhatsApp 등에서 사용

Signal Protocol

메시징 보안의 표준

현존하는 가장 강력한 보안 프로토콜입니다. Double Ratchet 알고리즘을 통해 메시지 단위의 개별 보안을 제공합니다.

  • X3DH 키 교환 + Double Ratchet 결합
  • 오프라인 메시지 암호화 완벽 지원

프로젝트 기술 스택 (Tech Stack)

  • Frontend: React + Vite 기반의 웹 클라이언트 / libsodium-wrappers
  • Backend: Python FastAPI + Uvicorn / 비동기 소켓 통신
  • Database: SQLite + SQLAlchemy (사용자 메타데이터 및 암호문 저장)
  • Cryptography: libsodium (NaCl), Curve25519, ChaCha20-Poly1305
  • Real-time: WebSocket을 이용한 실시간 양방향 메시지 중계

시스템 아키텍처 및 데이터 흐름

"Zero-Knowledge" 서버 설계

1. 모든 암호화/복호화는 브라우저에서 수행 (React + libsodium-wrappers-sumo)

2. 서버(FastAPI)는 opaque payload만 중계 — 평문도, 키 도출 과정도 보지 못함

3. 비밀키는 localStorage에만 저장. 공개키만 서버에 업로드

4. WebSocket으로 실시간 중계 + 오프라인 시 SQLite에 ciphertext 큐잉

Static — 실제 와이어 인스펙터

매 메시지 = ciphertext + nonce(24B 랜덤). 헤더·카운터 없음.

Static — X25519 정적 키 (현재 베이스라인)

사용자마다 X25519 키쌍 한 개를 영구 보관. 핸드셰이크 없이 매 메시지마다 새 nonce와 ciphertext만 전송.

와이어 필드
ciphertext 평문 + 16B Poly1305 MAC (base64)
nonce 24B 랜덤 (재사용 금지)
특징
장점 단순, 비동기 OK, 오버헤드 최소
한계 Forward Secrecy 없음 — 키 유출 시 모든 과거 메시지 노출
라이브러리libsodium · crypto_box (X25519 + XSalsa20-Poly1305)

Noise XX — 실제 와이어 인스펙터

3-msg 핸드셰이크 이후 transport는 counter + ct만

Noise XX — 상호 인증 핸드셰이크 + Transport

3-message 핸드셰이크로 ephemeral 키 교환 + 정적 키 상호 인증. 이후 transport는 헤더 없이 카운터 기반 nonce로만 암호화.

핸드셰이크 (1.5 RTT)
→ msg1 e (32B ephemeral pub)
← msg2 e, ee, s(암호화), es
→ msg3 s, se → Split → k_send / k_recv
Transport
counter 양쪽이 카운트 (implicit nonce)
ct + tag ChaCha20-Poly1305(k_send, ...)
구현libsodium 직접 조합 (crypto_scalarmult / HKDF / AEAD)

Signal — 실제 와이어 인스펙터

첫 msg = X3DH preamble, 이후 매 msg = header(dh/n/pn) + ct

Signal — X3DH + Double Ratchet

비동기 세션 시작 (X3DH) + 매 메시지마다 키 갱신 (Double Ratchet). Forward Secrecy + Post-Compromise Security 양쪽 모두 제공.

X3DH (첫 메시지 preamble)
IK_A / EK_A 송신자 identity + ephemeral pub
opk_id 소비한 OPK 번호 → SK = KDF(4×DH)
Double Ratchet
header.dh DH ratchet 공개키 — 답장마다 새로
header.n 같은 DH 내 메시지 번호
header.pn 직전 turn 메시지 수 (out-of-order)
ct + tag MK로 AEAD (MK는 1회 후 폐기)
구현libsodium + 자체 X3DH/DR 로직 (~350 LOC)
